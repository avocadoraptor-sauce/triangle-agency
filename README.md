# Basic Project Structure

Overall, this app is a Django rest+websockets backend and a React frontend.

Django serves the react frontend via [Django Webpack Loader](https://github.com/django-webpack/django-webpack-loader).

This is not optimal for performance, but is much easier to deploy to free django hosts than
the alternatives.

### Django

The django code lives in `server/`.
This is a single-app django project where the configuration and application content
both live in the same folder (i.e. `server/`).

### React

The React code lives under `src/`.

### Specs

A bunch of json files, describing intended data models, live under `specs/`.

### Static Content

Static content is served from `static/`.

Some of the stuff here is tracked by git, and others are generated by build steps.

For now, the janky deployment process involves committing the front-end here and
pulling those built artifacts into the prod environment, but we will clean that up soon!

### Gen

Generated code lives under `gen/`.
Its contents are tracked by git merely for convenience, but if we had a real build system
all of that would be part of the build process.

### Data

For now this just stores data fixtures used to pre-populate the app database.

# Running the Project

1. Run `source env.sh` in the root of this repo.
   
   This `env.sh` script:

    - Sets up the virtual environment with dependencies from `requirements.txt`.
    - Sets up the test database tables and populates with initial test data.
    - Sets up node in the venv and installs frontend dependencies from `package.json`.
    - Sets up some useful aliases.

2. Manually build the front-end:

    In a designated terminal window, run the following to launch an auto-building
    process that will re-pack when sources change.

    ```bash
    npm run pack
    ```

    Alternatively to do a one-time build, run:
    ```bash
    npx webpack --mode=development
    ```

3. Launch the Back-end (that serves the pre-built front-end).

    If you are running this project in vscode, you can just press f5 or shift-f5
    or whatever keybinding you have for running your project's code.

# Contributing to this Project
### Changing the REST API

The REST API for this project is managed by [Django Ninja](https://django-ninja.dev/).

The Schemas documented by ninja are defined in `server/views.py`.

If those change, to update the typescript bindings for the REST schemas, run:

```bash
npm run gentypes
```

# Deploying to Production

Before starting, take care not to have any uncommitted changes.
On your development machine, run the following command:
```bash
./release.sh
```
The release.sh file packages the front end using webpack and commits them to a release branch.

On your 3rd party hosting website you will need to clone the available release branch. 
If using a bash terminal, take the release branch name and replace it in the following command:
```bash
git clone -b <release/xxxxx> git@github.com:avocadoraptor-sauce/triangle-agency.git
```
Or if the clone is already available, simply pull & checkout to appropriate branch.

From PythonAnywhere, you can then just reload the application to see the new changes.
see url: https://www.pythonanywhere.com/user/<yourusername>/webapps
